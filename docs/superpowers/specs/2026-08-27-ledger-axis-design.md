# NEXT — 과거 금융이력 축 (Ledger) 설계

작성일 2026-08-27 · 근거 문서 `금융AI챌린지_회의록3.pdf`

---

## 0. 무엇을 만드는가

지금 NEXT는 입력원이 **인터뷰 답변 하나뿐**이다. `Profile → buildDesign() → 설계서 3종`.

여기에 **두 번째 입력원**을 붙인다. 사용자의 과거 금융 이력(`Ledger`)을 읽어 투자·소비 성향을
복제하고, 인터뷰에서 **말한 것**과 실제로 **한 것**을 대조한다. 그리고 판단력이 떨어지는 시점을
금융 바이오마커로 감지해, 사전에 정한 원칙이 자동으로 이어지게 한다.

회의록의 Phase 1(적재·복제) → Phase 2(감지·전환) → Phase 3(대행)을 한 축으로 관통시킨다.

---

## 1. 핵심 원칙 — Profile은 선언, Ledger는 관찰

두 상태를 끝까지 분리한다. 서로 덮어쓰지 않는다.

| | Profile | Ledger |
|---|---|---|
| 정체 | 인터뷰 답변 | 과거 금융 이력 |
| 저장 | `next.profile.v2` | `next.ledger.v1` |
| 의미 | 사용자가 **말한 것** | 사용자가 **한 것** |
| 설계서 생성 | 유일한 근거 | 근거 아님. 대조군 |

합치면 안 되는 이유: 이 서비스의 핵심 장면이 대조이기 때문이다.

```
Profile.answers.B11   "그대로 두고 팔지 않기"        ← 선언
Ledger.trades         2020-03 -18%에서 전량매도      ← 관찰
                      2022-06 -12%에서 60% 매도
                              ↓
                   contradiction — 신탁 제7조를 어느 쪽으로 쓸까?
```

Ledger가 `answers.B11`을 덮어쓰는 순간 "원래 뭐라고 했는지"가 사라져 질문 자체가 성립하지 않는다.

**Ledger가 answers를 쓰는 유일한 경우**는 사용자가 대조 화면에서 명시적으로 "이력대로"를
선택했을 때다. 그 사실은 `Contrast.resolution`에 남는다.

## 2. 데이터 흐름

```
Ledger                관찰 원본. 시드 고정 합성. 월별 집계 + 이벤트만 저장
  ↓ analyze(ledger, track)
LedgerInsight         행동적 자아 / 의사결정 자아 / 베이스라인
  ↓ contrast(profile, insight)
Contrast[]            문항별 선언 vs 관찰. aligned | tension | contradiction
  ↓ readBiomarker(ledger, insight)
BiomarkerReading      0~100 스코어 + 신호 5종
  ↓ evaluateTrigger(reading, proof)
TriggerGate           2조건 게이트
  ↓ buildTimeline(profile, design, ...)
TimelinePhase[]       30년 3구간 + 승인 주체
```

`buildDesign(profile, ledger?)` — 두 번째 인자는 **optional**. 없으면 기존과 완전히 동일하게 동작한다.

10년 실거래를 통으로 저장하면 localStorage가 넘친다. **월별 집계 120레코드 + 매매 이벤트 +
이상징후 이벤트**만 저장한다. 수십 KB.

## 3. 3층 구조 — 측정 / 판정 / 서술

| 층 | 담당 | 예시 | 키 없을 때 |
|---|---|---|---|
| **측정** | 룰 (순수 함수) | `realizedStopLoss = -14.3%` | 동일 |
| **판정** | LLM 주, 룰 폴백 | "낙폭 초기 반응형. 단 2020년 건은 의료비와 겹침" | 구간 분류로 격하 |
| **서술** | LLM | 문단 생성 | 템플릿 |

### 측정층이 룰인 이유

중앙값·회귀 기울기·비율은 산술이다. LLM에 맡기면 (1) 틀릴 때가 있고 (2) **같은 입력에 다른
숫자가 나온다**. 심사 중 새로고침으로 -14.3%가 -13.8%가 되면 그 자리에서 신뢰를 잃는다.
단위 테스트도 불가능해진다.

### 판정층이 LLM인 이유

`riskAversion 0.62`에서 성향 규정을 뽑는 건 if문으로 쓰면 티가 난다. 더 결정적으로, 숫자만으로는
가릴 수 없는 것이 있다.

> 2020-03 전량매도가 **패닉셀**인가, 그때 의료비 4,200만원이 나가 **현금이 필요했던 것**인가.

매매 이벤트 하나로는 답이 안 나온다. 같은 시점 다른 계좌 흐름과 함께 읽어야 하는 다변량 맥락
추론이다. 실제 마이데이터로 확장하면 가맹점명·적요 같은 비정형 텍스트가 붙어 더욱 그렇다.

### 측정층이 판정층을 감사 가능하게 만든다

LLM이 "패닉셀러"라고만 하면 믿을 수 없다. 근거가 룰로 고정돼 있으므로 판정 문장 옆에 항상
근거 매매가 함께 뜨고, 사용자가 직접 반박할 수 있다.

### 폴백의 한계 (명시)

키가 없을 때 룰 폴백은 **동등한 대안이 아니다.** `riskAversion > 0.5 → "손실 회피 경향이
관측됩니다"` 수준의 구간 분류다. 화면 구조와 숫자는 유지되지만 통찰은 밋밋하다.
폴백은 *데모가 죽지 않게 하는 보험*이다. 발표는 키가 있는 상태로 한다.

## 4. 엔진

### 4.1 `analyze.ts` — 성향 복제 (측정층)

**행동적 자아** (전 트랙) — `months[]`에서
월 생활비 중앙값, 고정비 목록과 평균 납부일, 계절 피크, 미사용 구독.

**의사결정 자아** (future · estate만) — `trades[]`에서

| 지표 | 계산 |
|---|---|
| `riskAversion` | 낙폭 대비 매도비중 회귀 기울기, 0~1로 정규화 |
| `realizedStopLoss` | 매도가 일어난 낙폭들의 중앙값 |
| `holdRate` | 낙폭 이벤트 중 매도하지 않은 비율 |
| `reactionDays` | 낙폭 시작 → 매도까지 평균 일수 |
| `allocation` | 최근 3년 평균 주식:채권:현금 |

**베이스라인** (전 트랙) — 월 거래건수·평균금액·야간비율·신규수취인빈도·연체율.

> **함정.** 베이스라인을 10년 전체 평균으로 잡으면 안 된다. 말년의 이상 신호가 기준선에
> 섞여 들어가 정작 감지가 무뎌진다. **건강기 앞 5년(`baselineYears`)만** 사용한다.

### 4.2 `contrast.ts` — 대조

관찰 가능한 문항에만 붙는 매핑 테이블을 둔다.

| 문항 | 선언 | 관찰 | 판정 |
|---|---|---|---|
| A02 · B07 · D09 | 생활비 입력액 | 실제 중앙값 | ±20% 밖이면 `tension` |
| A05 | 1회 이체 한도 | 과거 최대 이체액 | 한도 < 최대 → `contradiction` |
| A06 | 이상거래 룰 선택 | 실제 패턴 존재 | 있는데 안 고름 → `tension` |
| A01 · B10 · C09 | 고정지출 선택 | 실제 납부 항목 | 누락 → `tension` |
| **B11** | 운용지침 | `riskAversion` + `holdRate` | **핵심 대조** |
| B15 · D13 | 금지행위 선택 | 과거 실제 행위 | 과거에 한 걸 금지 → `aligned` (자기인식) |

해소는 3택: **선언대로 / 이력대로 / 절충**. `resolution`에 기록하며, "이력대로"일 때만
`answers`를 갱신한다.

### 4.3 `biomarker.ts` — 감지와 트리거

베이스라인 이탈도 가중합, 0~100. 신호 5종: 잔액오류 반복 / 이중입금 / 공과금 연체 /
야간고액 급증 / 신규수취인 고액이체. 구간 `0-30 정상 · 31-60 주의 · 61+ 경보`.

**트리거 2조건 게이트** (회의록 "논의 완료" 항목)

```
AI 경보 (61+)                              ← 이것만으로는 절대 발동하지 않는다
      +
최근 1개월 이내 의사 진단서 OR 장기요양보험 등급 발행서
      =
                        전환 발동
```

"AI가 판단해서 자산을 옮긴다"가 아니라 "AI는 알리기만 하고, 사람이 서류로 확인해야 움직인다".

### 4.4 `timeline.ts` — 30년 축

Phase 1(1~10년) · 2(11~15년) · 3(16~30년). 각 구간의 조항 발동과 **승인 주체**를 표시한다.

| 단계 | 범위 | 승인 |
|---|---|---|
| 1 | 공과금 자동납부, 미사용 구독 정리, 이상거래 1차 블록 | AI 독자 |
| 2 | 정기 리밸런싱 / 안전자산 전환 / 한도초과 의료비 | 본인 → 보호자 |
| 3 | 부동산 매각, 대규모 원금인출, 고액 증여, 핵심계약 해지 | 법적 후견인 · 전문가 |

기존 `lib/design/scenario.ts`(938줄)는 **수정하지 않는다.** 타임라인이 상위 뷰로 얹히고
각 Phase 안에서 기존 `scenariosFor()` 결과를 구간별로 필터해 재사용한다.

## 5. 화면

```
/  →  /start  →  /ledger  →  /interview  →  /plan  →  /simulation
      게이트      신규        수정          수정      확장
```

`/ledger`는 **게이트 뒤**에 온다. 트랙별로 추출량이 다르고, 특히 caregiver의
*"대리인은 부모님 마이데이터를 열 수 없습니다"* 경고는 트랙을 알아야 띄울 수 있다.

### 적용 범위 — 전 트랙 · 선택적 · 추출량 차등

| 트랙 | 추출 |
|---|---|
| daily | 소비패턴 · 이상거래 룰셋 개인화 (신탁 언급 없음) |
| future · estate | + 투자성향 복제 |
| caregiver | **불러올 수 없음.** 그 사실 자체를 경고로 보여준다 |

건너뛰기는 상시 개방한다.

### 신규 `/ledger`

① 연동 (시드 생성, 실제 마이데이터 연동 자리는 인터페이스로 비워둠)
② 적재 (10년 스파크라인 — 생활비 / 고정비 / 매매 / 연체)
③ 성향 (측정 지표 + 판정 문단 + 근거 목록)

### 수정 `/interview`

버블 스트림은 건드리지 않는다. `QuestionInput` 옆 사이드 카드만 붙인다. 대조 매핑에 있는
문항에서만 뜬다. 답한 즉시 대조가 돌고 `tension` 이상이면 3택이 뜨지만, **인터뷰를 멈추지
않는다** — 미루고 `/plan`에서 처리해도 된다.

### 수정 `/plan`

`TabKey`에 `contrast` 추가. 기존 4탭은 그대로.
`gaps`는 *안 채운 칸*, `contrast`는 *채웠는데 사실과 어긋나는 칸*.

### 확장 `/simulation`

상단에 30년 축 + 트리거 게이트 카드. 하단 노드 렌더링은 그대로 재사용.

## 6. 검증

### 테스트하는 것

| 대상 | 방법 | 이유 |
|---|---|---|
| 측정층 | 시드 고정 골든값 | 숫자가 흔들리면 데모가 죽는다 |
| 대조 판정 규칙 | 문항별 경계값 | ±20% 임계, 한도 < 최대 등 |
| 베이스라인 구간 분리 | 앞 5년만 쓰는지 | 틀리면 감지가 통째로 무뎌진다 |
| **트리거 게이트** | **한 조건만으로 발동하지 않는지** | 여기가 뚫리면 서비스 논리가 붕괴한다 |
| 룰 폴백 | 키 없이 전 구간 완주 | 오프라인 데모 보험 |

### 테스트하지 않는 것

LLM 출력 문장(비결정적), UI 스냅샷, 합성 데이터의 현실성. 판정층은 **출력 스키마 계약만**
검사하고 내용은 보지 않는다.

### 러너

레포에 테스트 인프라가 없어 `vitest`를 devDependency로 추가한다. 런타임 번들에 들어가지
않으며 오프라인 `npm run dev` 요건에 영향이 없다.

## 7. 구현 순서

각 단계가 끝날 때마다 독립적으로 시연 가능하다.

1. **기반** — 타입, 시드 생성기, store, 측정층, 데모 A~D 대응 시드 4종
2. **Phase 1 화면** — `/ledger` 3단, caregiver 경고
3. **대조** — 매핑 테이블, 룰 판정, `/plan` 탭, `/interview` 사이드 카드
4. **Phase 2·3** — 바이오마커, 트리거 게이트, 타임라인, `/simulation` 30년 축
5. **판정층** — `/api/ai/narrate`, 성향·대조 해석 LLM 승격

5단계 전까지 키 없이 전 구간이 돌아간다. 폴백이 먼저 깔리므로 LLM은 언제 붙여도 앞 단계를
흔들지 않는다.

## 8. 표현 원칙 (PRD §14 연장)

회의록은 IRL · TFT · LSTM-Autoencoder를 적용 모델로 적고 있으나, 본 구현에서 실제로 도는 것은
결정론적 지표 계산과 파운데이션 모델 호출이다. 화면에는 **"관측 지표"**로 표기하고,
회의록의 모델명은 다음 각주로 분리한다.

> 본 구현은 규칙 기반 측정 + 파운데이션 모델 판정입니다. 피처별 전용 모델(IRL · TFT 등)
> 적용은 후속 과제입니다.

바이오마커 스코어는 진단이 아니다. 화면 어디에서도 "인지장애입니다"라고 쓰지 않는다.
"평소 패턴과 달라진 지점이 관측됩니다"까지만 쓴다.
