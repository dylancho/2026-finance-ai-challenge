# 심사용 예시 데이터 설계안

> **상태: 검토안. 아직 구현하지 않았습니다.**
> 현재 코드의 데모 프로필(A~D)은 그대로이며, 이 문서는 심사용 예시 데이터를 새로 만든다면
> 어떤 값이어야 하는지를 정리한 것입니다. 채택 여부는 팀에서 정합니다.

**41문항 전부 답한 상태**로 설계한다. 다섯 챕터를 모두 채워야 신탁설계서와 후견설계서,
지출설계서가 빠짐없이 나오고 세 가지 산출물이 온전히 보인다.

```
①  금융데이터 이상감지        ②  필수생활비 이체        ③  전문가 이양의뢰서
```

---

## 챕터를 다 채워야 하는 이유

챕터 조합별로 무엇이 나오는지 직접 돌려 확인했다.

| 조합 | 신탁설계서 | 후견설계서 | 이상거래 룰 |
|---|---|---|---|
| 코어만 (11문항) | **없음** | **없음** | 4개 |
| 코어 + 보호 (15) | 없음 | 없음 | 7개 |
| 코어 + 의료 (15) | 11개 조항 | 임의후견 | 4개 |
| **전 챕터 (41)** | **11개 조항 + 상속 반영** | **임의후견** | **7개** |

**코어만으로는 의뢰서가 빈 껍데기가 된다.** 신탁도 후견도 안 나와서 확정된 지시사항이 0개다.

의료 챕터가 신탁과 후견을 여는 열쇠이고, 상속 챕터가 신탁의 수익자·잔여재산 조항을 채우며,
보호 챕터가 이상거래 룰을 4개에서 7개로 늘린다. 투자 챕터는 운용지침 조항과 선언·관찰
대조를 만든다. **넷 다 필요하다.**

## 이상거래 시연용 거래 두 건

`/fraud-shield` 화면에 표시될 당일 거래다.

| | 거래 A | 거래 B |
|---|---|---|
| 금액 | **250만원** | **760만원** |
| 수취인 | 처음 보는 개인 계좌 | 처음 보는 개인 계좌 |
| 시각 | 오후 2시 | **새벽 2시 15분** |
| 인증 | 정상 | **비밀번호 2회 오류** |
| 기기 | 평소 기기 | **처음 쓰는 기기** |
| 결과 | **검토** — 한도(300만)는 통과했으나 처음 보는 계좌라 S02 기준(200만)에 걸림 | **차단** — 금액·시간·인증·기기 네 신호가 겹침 |

> 거래 A가 이 서비스의 차별점이다. **한도만 보는 기존 방식이라면 그냥 나갔을 거래**를
> 맥락으로 잡는다. 두 거래 모두 처음 보는 계좌로 둔 것은 금액과 맥락 중 무엇이 판정을
> 갈랐는지를 한눈에 비교하게 하기 위해서다.

# 세 축이 화면에서 어떻게 보이나

### ① 금융데이터 이상감지

```
/ledger          10년 추이 · 생활비 중앙값 162만 · 바이오마커 72점 경보
/plan 대조 탭    "팔지 않기" ↔ "5회 중 4회 매도"
                 "한도 300만" ↔ "과거 최대 760만"
/fraud-shield    250만원 → 검토 / 760만원 → 차단, 신호별 점수와 해설
/simulation      30년 축 2구간에서 경보. 진단서 첨부 전에는 무엇이 빠졌는지 표시
```

### ② 필수생활비 이체

```
/plan 지출설계서  3층 계좌 · 자동이체 4건 월 94만원 · 정기지급 190만원
                  잔액 부족 시 예비계좌 충당 · 한도 정책 · 이상거래 룰 7종
                  자산 소진 추정 차트
/simulation       생활비 자동 지급 개시 단계가 조항을 인용하며 진행
```

### ③ 전문가 이양의뢰서

```
/plan 신탁설계서   수익자연속신탁 · 제1조 ~ 제11조
/plan 후견설계서   임의후견 판정 · 로드맵 4단계 · 신상보호 사무범위
/referral ①       체결 대상 문서 3종과 각각의 효력 발생 시점
/referral ②       수신처 NH농협은행 WM·신탁부서 (이력에서 읽은 값 + 근거)
                   조항별 근거 문항 번호 · 참조 법령 조문 전문 · 부록 41문항
/referral ③       보호자 이정숙에게 전달 → 12시간 무응답 시 승계
/simulation        집행 근거 전부 해제 시 1단계부터 잠김
                   신탁만 체결 시 지급은 되고 자동이체는 수동
```

차단 상태로 보인다.

# 두 번째 프로필은 만들지 않기를 권한다

진단받은 상태는 심사위원이 `/start`에서 직접 고르면 김영수의 답변을 그대로 둔 채 의사능력만
바뀌어 문서가 전환된다. 관리할 데이터가 하나로 끝나고, **같은 사람의 같은 답변이 시점 때문에
다른 문서가 되는** 장면이라 대비가 오히려 선명하다.

# 확인이 필요한 것 — 랜딩 숫자가 함께 바뀐다

새 랜딩의 숫자 섹션이 데모 프로필의 **실제 설계서를 돌려서** 값을 만든다. 하드코딩이 아니다.

```
현재  landingStats("B")  →  조항 22개 · 공백 1개 · 23년
```

41문항을 전부 채우면 **공백이 0개**가 된다. 랜딩 문구가 *"당신의 설계서에는 지금 몇 개의
공백이 있습니까"* 인데 0을 반환하면 그 문장과 어긋난다. 선택지는 둘이다.

- **랜딩은 계속 기존 프로필을 쓰고, 김영수는 새 키로 추가한다**
- 김영수의 문항 하나를 비워 공백 1개를 만든다

**전자를 권한다.** 랜딩은 온보딩 카피에 맞는 숫자를 쓰고 심사용 데모는 완성된 상태를
보여주는 편이 각자의 목적에 맞는다. 다만 이 판단은 랜딩을 만든 사람과 함께 정하는 편이 좋다.
