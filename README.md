# NEXT — AI Future Financial Decision Service

> **내가 결정할 수 없을 때를 위해, 지금의 내가 결정합니다.**
> 2026 금융 AI 챌린지 프로토타입

---

## 1. 서비스 소개

NEXT는 사용자가 스스로 금융 의사결정을 내리기 어려워질 상황을 대비해, AI와 대화하며 자신의 결정
원칙을 정리하고 이를 **신탁·후견·지출 설계서**라는 조항 수준의 문서로 산출합니다.

핵심은 세 가지입니다.

1. **목적을 먼저 묻습니다.** 공과금 관리가 필요한 사람에게 치매와 후견 이야기를 꺼내지 않습니다.
2. **의사능력 상태를 판정합니다.** 이미 진단을 받은 분에게 임의후견을 권하는 오류를 범하지 않습니다.
3. **산출물이 조항입니다.** "신탁을 검토해 보세요"가 아니라 제1조부터 제11조까지의 초안을 냅니다.

---

## 2. 문제 정의

치매·사고·질병으로 금융 의사결정 능력이 떨어지는 상황은 누구에게나 발생하지만, 대부분은 그 전에
아무것도 정해두지 않습니다. 제도가 없어서가 아닙니다.

- 신탁과 후견은 이미 존재하지만, **내 상황에 무엇이 맞는지** 판단하기 어렵습니다.
- **임의후견과 신탁은 의사능력이 있을 때만** 새로 설정할 수 있습니다. 시점을 놓치면 선택지가
  법정후견으로 좁아집니다.
- "주식은 급하게 팔지 말라"는 말은 기억으로 남을 뿐, 금융기관이 집행할 수 있는 조항이 되지 않습니다.

## 3. 주요 기능

### 3.1 게이트 — 목적을 먼저 묻는 3문항

| 단계 | 질문 | 역할 |
|---|---|---|
| G1 | 오늘은 무엇을 준비하러 오셨나요? | 4개 트랙 라우팅 |
| G2 | 이 설계는 누구를 위한 것인가요? | 본인 / 가족 대리 |
| G3 | **지금 금융 결정을 스스로 하실 수 있나요?** | 제도 가부 결정 |

G3이 서비스의 지적 중심입니다. `이미 진단을 받으셨습니다`를 고르면 **신탁설계서가 생성되지 않고**,
그 이유와 법정후견 경로, 지금 당장 가능한 계좌 보호 조치를 대신 제시합니다.

### 3.2 4개 트랙

| 트랙 | 질문 수 | 산출물 |
|---|---|---|
| A. 일상 지출·공과금 | 8 | 지출설계서 (약 2분) |
| B. 미래 판단력 저하 대비 | 22 (6섹션) | 신탁 + 후견 + 지출 |
| C. 가족을 대신한 준비 | 14 | 후견 + 지출 |
| D. 상속·증여 연계 | 16 | 신탁 + 지출 |

질문 타입은 6종입니다 — `choice` / `multi(+항목별 금액)` / `amount(슬라이더)` / `person` /
`allocation(자산→수증자 매트릭스)` / `open`. 자유 입력은 항상 열려 있습니다.

모든 질문은 `mapsTo`로 **설계서의 특정 조항에 연결**되어 있고, 인터뷰 우측에 조항이 실시간으로
쌓입니다. 사용자는 설문이 아니라 문서를 작성하고 있다고 느낍니다.

### 3.3 산출물 — 조항 수준 설계서 3종

**신탁설계서** — 유형 판정(자익신탁 / 유언대용 / 수익자연속 / 부동산관리 / 후견지원)과 근거·대안,
제1조 목적부터 제11조 잔여재산 귀속까지. 지급개시 트리거(제4조), 증액 조건이 포함된 정기지급(제5조),
금지행위(제8조), 신탁감독인(제9조)이 답변에 따라 실제 문장으로 생성됩니다.

**후견설계서** — 의사능력 → 임의후견 / 한정후견 / 특정후견 / 성년후견 **판정 트리**와
"해당하지 않는 제도가 왜 아닌지". 재산관리 9항목 × 신상보호 6항목을 `위임 / 동의유보 / 제외`로
표기하고, 효력 발생 요건과 단계별 로드맵(기간·서류·비용)을 냅니다.

**지출설계서** — 3층 계좌 구조(생활 / 의료예비 / 보전), 자동이체 매트릭스, 한도 정책,
이상거래 룰셋(조건 → 조치 → 통보), 승인·에스컬레이션 체계, 그리고 자산 소진 시점 추정 차트.

### 3.4 시뮬레이터 — 조항 발동 추적기

시나리오를 고르면 타임라인이 **실제 설계서 조항을 인용하며** 진행됩니다.

```
① 치매 진단 (전문의 2인 소견)      → 신탁 제4조 지급개시 트리거 충족
② 월 300만원 자동 지급 개시        → 신탁 제5조 · 지출 §2
③ 요양시설 입소                    → 신탁 제5조② 증액 트리거 (+180만)
④ 가족이 부동산 매각 시도          → 신탁 제8조 금지행위 → 차단
⑤ 큰 의료비 발생                   → 미설정. 여기서 흐름이 멈춥니다.
```

답하지 않은 항목에 도달하면 **빨간 정지 노드**가 나오고 이후 단계는 흐려집니다. 클릭하면 해당
질문으로 이동해 조항을 채우고 돌아올 수 있습니다.

### 3.5 하이브리드 AI

```
자유 입력 → [룰 엔진] 항상 실행 (오프라인 100%)
                ↓ 신뢰도 0.6 미만일 때만
           [LLM] /api/ai/parse — ANTHROPIC_API_KEY 있을 때만, 2.5초 타임아웃
                ↓ 실패·미설정 시 즉시 룰 결과 사용
           추출 결과를 칩으로 표시 → 사용자가 확인·수정
```

룰 엔진은 한국어 금액 파서(`삼백만원` `1억 2천만원` `5,000,000원` `월 300`), 관계·이름 파서
(조사 제거 포함), 질문별 의도 사전, 그리고 **좁은 범위의 부정 처리**를 갖습니다.
UI에는 `규칙 추출` / `AI 추출` 중 무엇이 쓰였는지 표시됩니다.

## 4. 실행 방법

```bash
npm install
npm run dev        # http://localhost:3000
```

프로덕션 확인:

```bash
npm run build && npm start
```

> `npm run dev` 와 `npm run build` 를 **동시에 실행하지 마세요.** 둘 다 `.next` 에 쓰기 때문에
> 렌더러가 멈춘 것처럼 보일 수 있습니다.

### 데모 모드

| URL | 내용 |
|---|---|
| `/plan?demo=B` | 완성도 91%의 신탁설계서. 제6조만 비어 있음 |
| `/simulation` (B 로드 후) | 치매 진단 시나리오 — 5번 노드에서 정지 |
| `/plan?demo=C` | 진단을 받은 부모님 케이스. **신탁 생성 차단 + 성년후견 판정** |
| `/plan?demo=A` | 공과금만 관리하는 경량 트랙 |
| `/plan?demo=D` | 상속·증여. 유류분 경고 포함 |

### LLM 연결 (선택)

```bash
# .env.local
ANTHROPIC_API_KEY=sk-ant-...
```

설정하지 않아도 전 기능이 동작합니다. 키가 없으면 `/api/ai/parse` 는 204를 반환하고 클라이언트는
룰 엔진 결과를 그대로 사용합니다.

## 6. 프로젝트 구조

```
app/
  page.tsx            랜딩
  start/              게이트 3문항
  interview/          트랙별 인터뷰
  plan/               설계서 3종 + 공백 목록
  simulation/         조항 발동 추적
  api/ai/parse/       선택적 LLM 엔드포인트

lib/
  types.ts            공용 타입
  profile.ts          상태·localStorage·데모 프로필
  format.ts           한국어 금액 포맷 (300만원 / 2억 5,000만원)
  questions/          gate · daily · future · caregiver · estate
  ai/                 rules(룰 엔진) · engine(하이브리드)
  design/             trust · guardianship · expense · gaps · scenario

components/
  layout/ common/ gate/ interview/ plan/ simulation/
```

**설계 엔진은 순수 함수입니다.** `Profile → Design`. React에 의존하지 않아 단독으로 테스트할 수
있고, 이 구조 덕분에 4개 트랙 전체를 Node에서 검증했습니다.

## 9. 금융·법률 고지

**본 서비스는 해커톤 데모용 프로토타입입니다.**

- 실제 계약 체결, 자산 이동, 금융상품 가입, 후견인 지정을 **수행하지 않습니다.**
- 생성되는 설계서는 AI가 사용자의 답변을 정리한 **초안이며 법적 효력이 없습니다.**
- 신탁·후견 제도의 실제 이용 가능 여부, 조항의 유효성, 세무 효과는 금융기관·변호사·법무사 등
  전문가의 확인이 필요합니다.
- 절차의 기간·비용은 사건과 관할 법원에 따라 달라지며, 본 서비스가 제시하는 수치는 일반적인
  범위를 참고용으로 정리한 것입니다.
- 실제 금융기관 API·개인정보·실계좌를 사용하지 않습니다. 모든 입력은 브라우저 localStorage에만
  저장되며 서버로 전송되지 않습니다. (LLM 경로를 켠 경우, 해당 문장만 파싱을 위해 전송됩니다.)
